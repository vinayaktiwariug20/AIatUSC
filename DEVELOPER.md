# Doorstep developer guide

One page for whoever looks after Doorstep next. Setup from scratch is in
[CLOUDFLARE_EN.md](CLOUDFLARE_EN.md); the indoor viewer is in
[outdoor-nav/INDOOR_HANDOFF.md](outdoor-nav/INDOOR_HANDOFF.md); the AI service is in
[outdoor-nav/AI_SERVICE.md](outdoor-nav/AI_SERVICE.md). Staff-facing help is the page
`/staff-guide/` (source: `outdoor-nav/outdoor/static/staff-guide/index.html`).

## How a change goes live

1. Branch from `main`, make the change, open a pull request.
2. GitHub Actions runs on every PR: builds `graph.json` from `data/`, then the JS tests,
   Python tests and the Python/JS route parity check.
3. Merge to `main`: the same checks run, then the deploy job applies any new D1
   migration (`migrations/`) and deploys the Worker. Nothing to do by hand.

Secrets never live in the repo. Cloudflare (Worker → Settings → Variables and Secrets):
`ADMIN_TOKEN`, `ORS_API_KEY` (driving), `AI_URL` and `AI_SECRET` (assistant). GitHub
(repo → Settings → Secrets → Actions): `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`.
The repo is public: never commit a token, and never paste one into a doc or chat.

Before pushing more commits to a PR, check it hasn't been merged (`gh pr view N`).
Commits pushed to a merged branch never reach `main`.

## Where things are (`outdoor-nav/`)

| Path | What |
|---|---|
| `cloudflare/api.mjs` | Every API route; staff roles (`requireStaff`, `requireAdmin`) |
| `cloudflare/mobility.mjs` | Gates, parking structures, statuses, prices, driving, soft gates |
| `cloudflare/router.mjs` | Walking router (mirrored by `outdoor/router.py`; parity is tested) |
| `cloudflare/assistant.mjs` | Facts given to "Ask Doorstep" |
| `cloudflare/staffkeys.mjs`, `adminguard.mjs` | Staff keys; wrong-token lockout |
| `outdoor/static/` | The pages: map (`index.html`), `indoor/`, `create/` (event links), `survey/`, `staff-guide/`, `privacy/`, `stats/`, door photos in `doors/` |
| `data/` | All map facts (below). Edit these, not `graph.json` |
| `cloudflare/graph.json` | Generated by `npm run build:graph`; never edit by hand |
| `migrations/` | D1 tables, numbered; add a new file, never edit an applied one |
| `tests/` | `node --test` files; Python tests in `tests/test_outdoor.py` |

## Common changes

After any change in `data/`, run `npm run build:graph`. If two PRs both touched data,
`graph.json` will conflict: take either side and rebuild it; it is generated.

- **Gate hours** (`data/gates.json`): vehicle hours per `weekday` / `weekend` / `holiday`;
  `pedestrian_hours` from Transportation's schedule, with `uncertain` windows for the hour
  DPS may open or close late. When a gate is seen to differ from the schedule, a
  `pedestrian` entry with `observed` (and `locked: true` if it's kept locked) wins; keep
  the schedule's hours in a `_pedestrian_note`.
- **Gate pins** (`data/mobility.json` `gates`): `location_source: "team_pin"` for real
  pins. A closed gate becomes a 12 m no-drive circle; if the pin is within ~15 m of a
  public street, add `area: [lat, lon]` a little inside campus (see Royal), or Doorstep
  will refuse routes along that street. `pedestrian_only: true` for foot gates.
- **A door** (`data/entrances.override.json`): `building`, `id`, `name` (what people see
  on arrival), `lat`/`lon`, `wheelchair` (true only if surveyed step-free), `photo`
  (`/doors/<id>.jpg`, 800 px, location data removed, people blurred), `indoor_node` if the
  indoor map starts there, `replace_osm` to drop OpenStreetMap's guesses, `_source`.
- **A parking structure or lot**: car entrance and walk-out points in `data/surveyed.json`;
  an entry in `mobility.json` `parking` with `gate`, `entrance`, `exit` and `access`
  options. Entrances that connect by campus roads (Royal, McClintock, Downey Way, Watt Way)
  can all be access options; Jefferson Blvd. and McCarthy Way reach only their own
  structure (see `campus_roads_note`). An option can carry `windows` (e.g. Shrine's 32nd St
  entrance, weekdays 6–6).
- **Prices**: `published_rates` per structure, from USC Transportation's yearly "Hourly and
  All Day Parking Availability" PDF (`rates_source`). Update them each fiscal year. Staff
  post exceptions (events, free days) on the Staff screen; those are stored in D1.
- **Football dates**: `data/football.json`, once a season.
- **Field surveys**: the `/survey/` page exports JSON (GPS averaged, optional paced
  distance and compass bearing). Check each point against the building outline before
  adding it; a point well inside another building is usually a bad fix.

## Checks

```bash
npm test               # JS: Worker + D1 in memory
npm run check:parity   # Python and JS routers agree
cd outdoor-nav && python -m pytest -q
```

For a quick look in a browser without Cloudflare: `npm run dev` (needs `npm install`,
which brings Wrangler). Staff features need `npm run db:local` first.

## Rules the team keeps

- Only restrict, never open: no staff action may send anyone through a gate the schedule
  keeps shut.
- No personal data: no accounts; usage counts are anonymous; addresses typed by users go
  only to the geocoders named on the privacy page.
- Don't scrape maps.usc.edu or Concept3D. OpenStreetMap data is ODbL; keep the credit.
- Stage files by name (`git add path`), never `git add -A`: the repo folder holds
  untracked team files.
